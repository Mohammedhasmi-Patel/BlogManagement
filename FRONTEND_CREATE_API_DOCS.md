# Frontend API Documentation: Create Functionalities

This document contains complete integration guidelines, request/response contracts, validation constraints, TypeScript interfaces, and code examples for all **Create** endpoints in the BlogManagement API.

---

## 1. Global API Standards & Base Configuration

### Base URL
- **Development**: `http://localhost:5027`
- **Environment Variable**: `VITE_API_BASE_URL` / `NEXT_PUBLIC_API_BASE_URL`

### Unified API Response Structure (`ApiResponse<T>`)
Every endpoint returns a consistent JSON envelope:

```typescript
export interface ApiResponse<T> {
  success: boolean;
  statusCode: number;
  message: string;
  data: T | null;
}
```

#### Success Response (`2xx`)
```json
{
  "success": true,
  "statusCode": 201,
  "message": "Resource created successfully.",
  "data": { ... }
}
```

#### Error Response (`4xx` / `5xx`)
```json
{
  "success": false,
  "statusCode": 400,
  "message": "Error description message.",
  "data": null
}
```

## 3. Create Category API

Creates a new blog category associated with the authenticated author. A unique slug is automatically generated by the backend based on the category name.

- **Method**: `POST`
- **Route**: `/api/categories`
- **Content-Type**: `multipart/form-data`
- **Authentication**: `Bearer <JWT_TOKEN>` (Must belong to a user with role `Author`)

### 3.1 Request Payload (`CreateCategoryRequestDTO`)

Send parameters as **`multipart/form-data`** (form fields, NOT JSON body):

| Field | Type | Required | Validations / Constraints | Description |
| :--- | :--- | :--- | :--- | :--- |
| `name` | `string` | **Yes** | Min 3, Max 55 chars. Must be unique for the user. | Name of the category |
| `description` | `string` | No | Optional. If provided, min 10, max 255 chars. | Brief summary of the category |
| `icon` | `File` (binary) | No | Optional. Max size **5MB**. Allowed extensions: `.jpg`, `.jpeg`, `.png`, `.webp`, `.svg`. | Category icon/image file |

> **Note**: Do not pass empty strings for `description` or `icon`. If no file is selected, simply omit `icon` from the `FormData`.

### 3.2 Response Payload (`CategoryResponseDTO`)

#### `201 Created` — Success Response
```json
{
  "success": true,
  "statusCode": 201,
  "message": "Category created successfully.",
  "data": {
    "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "name": "Artificial Intelligence",
    "slug": "artificial-intelligence",
    "description": "Articles covering machine learning, deep learning, and LLMs.",
    "icon": "/uploads/categories/3fa85f64-icon.png"
  }
}
```

### 3.3 Error Responses

#### `400 Bad Request` — Validation Failure or Duplicate Name
```json
{
  "success": false,
  "statusCode": 400,
  "message": "Category name exist",
  "data": null
}
```
*Other validation error messages:*
- `"Category name is required."`
- `"Category name must be at least 3 characters long."`
- `"Category name must not exceed 55 characters."`
- `"Description must be at least 10 characters long."`
- `"Description must not exceed 255 characters."`
- `"Icon file size must not exceed 5MB."`
- `"Only .jpg, .jpeg, .png, .webp, and .svg files are allowed."`

#### `401 Unauthorized` — Missing or Invalid JWT Token
```json
{
  "success": false,
  "statusCode": 401,
  "message": "Unauthorized.",
  "data": null
}
```

#### `403 Forbidden` — User is not an `Author`
```json
{
  "success": false,
  "statusCode": 403,
  "message": "You do not have permission to access this resource.",
  "data": null
}
```

## 4. Register User API (Account Creation)

Registers a new user account (either `Author` or standard `User`) and returns an authentication JWT token.

- **Method**: `POST`
- **Route**: `/api/auth/register`
- **Content-Type**: `multipart/form-data`
- **Authentication**: None (Public)

### 4.1 Request Payload (`RegisterUserRequestDTO`)

Send parameters as **`multipart/form-data`**:

| Field | Type | Required | Validations / Constraints | Description |
| :--- | :--- | :--- | :--- | :--- |
| `firstName` | `string` | **Yes** | Max 50 chars | User's first name |
| `lastName` | `string` | **Yes** | Max 50 chars | User's last name |
| `role` | `string` | **Yes** | Allowed values: `"Author"` or `"User"` (`"Admin"` is forbidden) | Target role |
| `email` | `string` | **Yes** | Valid email format, Max 100 chars. Must be unique. | User email address |
| `password` | `string` | **Yes** | Min 6 characters. | Account password |
| `confirmPassword` | `string` | **Yes** | Must match `password` exactly. | Password confirmation |
| `avatar` | `File` (binary) | No | Optional. Allowed extensions: `.jpg`, `.jpeg`, `.png`. | Profile picture file |
| `bio` | `string` | No | Optional. Max 500 chars. | Brief bio description |

### 4.2 Response Payload (`RegisterUserResponseDTO`)

#### `201 Created` — Success Response
```json
{
  "success": true,
  "statusCode": 201,
  "message": "User registered successfully.",
  "data": {
    "id": "e4c5b3a1-7e89-4a92-91e8-78229b0df111",
    "email": "author@example.com",
    "firstName": "John",
    "lastName": "Doe",
    "avatar": "http://localhost:5027/uploads/users/avatar.jpg",
    "bio": "Tech writer and software architect.",
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJlbWFpbCI6ImF1dGhvckBleGFtcGxlLmNvbSIsIm5hbWVpZCI6ImU0YzViM2ExLTdlODktNGE5Mi05MWU4LTc4MjI5YjBkZjExMSIsInJvbGUiOiJBdXRob3IiLCJleHAiOjE3NTU5NjAwMDB9...",
    "createdAt": "2026-08-22T18:30:00Z"
  }
}
```

### 4.3 Error Responses

#### `400 Bad Request` — Validation / Registration Failure
```json
{
  "success": false,
  "statusCode": 400,
  "message": "Passwords do not match.",
  "data": null
}
```
*Common error messages:*
- `"First name is required."` / `"First name must not exceed 50 characters."`
- `"Last name is required."` / `"Last name must not exceed 50 characters."`
- `"Invalid user role."`
- `"A valid email address is required."`
- `"Password must be at least 6 characters long."`
- `"Only .jpg, .jpeg, and .png files are allowed."`

#### `409 Conflict` — Email Already Registered
```json
{
  "success": false,
  "statusCode": 409,
  "message": "User with this email already exists.",
  "data": null
}
```

## 6. Frontend Integration Code Examples

### 6.1 Create Category (Axios Example)

```typescript
import axios, { AxiosError } from 'axios';
import { ApiResponse, CategoryResponse, CreateCategoryRequest } from './types/api';

const apiClient = axios.create({
  baseURL: 'http://localhost:5027/api',
});

export async function createCategory(
  payload: CreateCategoryRequest,
  token: string
): Promise<CategoryResponse> {
  const formData = new FormData();
  formData.append('Name', payload.name.trim());

  if (payload.description && payload.description.trim()) {
    formData.append('Description', payload.description.trim());
  }

  if (payload.icon) {
    formData.append('Icon', payload.icon);
  }

  try {
    const response = await apiClient.post<ApiResponse<CategoryResponse>>(
      '/categories',
      formData,
      {
        headers: {
          Authorization: `Bearer ${token}`,
          // Note: Axios automatically sets the Content-Type to multipart/form-data with boundary
        },
      }
    );

    if (!response.data.success || !response.data.data) {
      throw new Error(response.data.message || 'Failed to create category.');
    }

    return response.data.data;
  } catch (error) {
    if (axios.isAxiosError(error) && error.response?.data) {
      const apiError = error.response.data as ApiResponse<null>;
      throw new Error(apiError.message || 'Error occurred while creating category.');
    }
    throw error;
  }
}
```

### 6.2 Create Category (Native `fetch` Example)

```typescript
import { ApiResponse, CategoryResponse, CreateCategoryRequest } from './types/api';

export async function createCategoryFetch(
  payload: CreateCategoryRequest,
  token: string
): Promise<CategoryResponse> {
  const formData = new FormData();
  formData.append('Name', payload.name);

  if (payload.description) {
    formData.append('Description', payload.description);
  }

  if (payload.icon) {
    formData.append('Icon', payload.icon);
  }

  const response = await fetch('http://localhost:5027/api/categories', {
    method: 'POST',
    headers: {
      Authorization: `Bearer ${token}`,
      // IMPORTANT: DO NOT set 'Content-Type': 'multipart/form-data'. 
      // The browser must automatically set it along with the boundary string.
    },
    body: formData,
  });

  const result: ApiResponse<CategoryResponse> = await response.json();

  if (!response.ok || !result.success || !result.data) {
    throw new Error(result.message || 'Failed to create category.');
  }

  return result.data;
}
```

### 6.3 Register User (Axios Example)

```typescript
import axios from 'axios';
import { ApiResponse, RegisterUserRequest, RegisterUserResponse } from './types/api';

export async function registerUser(
  payload: RegisterUserRequest
): Promise<RegisterUserResponse> {
  const formData = new FormData();
  formData.append('FirstName', payload.firstName);
  formData.append('LastName', payload.lastName);
  formData.append('Role', payload.role);
  formData.append('Email', payload.email);
  formData.append('Password', payload.password);
  formData.append('ConfirmPassword', payload.confirmPassword);

  if (payload.bio) {
    formData.append('Bio', payload.bio);
  }

  if (payload.avatar) {
    formData.append('Avatar', payload.avatar);
  }

  try {
    const response = await axios.post<ApiResponse<RegisterUserResponse>>(
      'http://localhost:5027/api/auth/register',
      formData
    );

    if (!response.data.success || !response.data.data) {
      throw new Error(response.data.message || 'Registration failed.');
    }

    return response.data.data;
  } catch (error) {
    if (axios.isAxiosError(error) && error.response?.data) {
      const apiError = error.response.data as ApiResponse<null>;
      throw new Error(apiError.message || 'Registration failed.');
    }
    throw error;
  }
}
```

## 7. Frontend Best Practices & Important Tips

1. **Do Not Set `Content-Type: multipart/form-data` manually**:
   - When sending `FormData` via `fetch` or `axios`, do **not** manually define the `Content-Type` header. Let the browser generate it automatically with the multi-part boundary (e.g. `multipart/form-data; boundary=----WebKitFormBoundary...`).
2. **Omit Optional Empty Fields**:
   - If an optional field like `description` or `bio` is empty, do not append an empty string or `"null"`. Either omit the key from `FormData` or only append if `value.trim().length > 0`.
3. **Role Validation on Registration**:
   - Ensure the dropdown/radio buttons for `Role` on the registration form only offer `"Author"` or `"User"`. `"Admin"` is restricted and will be rejected with HTTP 400.
4. **Token Persistence**:
   - After a successful `201 Created` from `/api/auth/register`, store `data.token` into `localStorage` / `sessionStorage` or cookies, and attach it to subsequent requests using the `Authorization: Bearer <token>` header.
5. **Handling Image Previews**:
   - Before uploading an icon/avatar, preview it locally using `URL.createObjectURL(file)` to enhance user experience. Clean up with `URL.revokeObjectURL()` on component unmount.
